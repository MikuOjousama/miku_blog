## 1. 项目目标

在外地使用 MacBook，通过互联网安全访问家中 Windows AI 工作站上的 ComfyUI，实现远程操作本地 GPU 进行 AI 图片生成。

实际部署环境：

- MacBook 位于江苏。
- Windows AI 工作站位于河北。
- 家庭工作站使用 RTX 4080 16GB。
- 腾讯云北京轻量应用服务器作为自建 Tailscale DERP 中继节点。
- Tailscale 负责设备之间的加密组网。
- Tailscale Serve 提供私有 HTTPS 访问入口。
- ComfyUI 运行在家里的 Windows 电脑上，模型推理由本地 GPU 完成。

**设计原则：**

1. 不开放 ComfyUI 的公网 8188 端口。
2. 不使用 Tailscale Funnel。
3. 图片生成和模型推理留在本地，不上传第三方生图平台。
4. 使用自建北京 DERP，改善跨地区中继延迟。
5. Mac 作为远程控制终端，家里的 Windows 作为 GPU 计算节点。

## 5. 腾讯云部署自建 DERP

### 5.1 创建 VPS

创建北京地域轻量应用服务器，系统选择 Ubuntu 24.04 LTS。本次使用以下配置：

- 2 核 CPU
- 4GB RAM
- 60GB SSD
- 5Mbps 带宽
- 500GB/月流量包

SSH 登录：

```bash
ssh ubuntu@x.x.x.x
```

### 5.2 更新系统

```bash
sudo apt update
sudo apt upgrade -y
```

### 5.3 安装 Go

从 Go 官方下载页获取发行包：

https://go.dev/dl/

本次使用 Go 1.27.4。下载后先校验 SHA256，再安装。

检查版本：

```bash
go version
```

### 5.4 编译安装 DERP

```bash
go install tailscale.com/cmd/derper@latest
sudo install -m 755 "$(go env GOPATH)/bin/derper" /usr/local/bin/derper
```

检查：

```bash
derper -help
```

### 5.5 首次启动 DERP 并生成证书

本次使用公网 IP 作为主机名，采用手动证书模式：

```bash
sudo derper \
  -a=:443 \
  -hostname=x.x.x.x \
  -certmode=manual \
  -certdir=/var/lib/derper/certs \
  -http-port=-1 \
  -stun-port=3478
```

首次运行时，DERP 会生成 IP 地址对应的自签名证书，并输出证书指纹。

本次证书指纹：

```text
sha256-raw:08ad…87b1（已截断）
```

证书目录：

```text
/var/lib/derper/certs
```

DERP 密钥默认位置：

```text
/var/lib/derper/derper.key
```

**不要随意删除或重建证书、密钥文件。** 否则可能导致证书指纹变化，或服务无法正常启动。

### 5.6 配置 systemd

创建服务文件：

```bash
sudo nano /etc/systemd/system/derper.service
```

写入：

```ini
[Unit]
Description=Tailscale DERP Relay Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/derper -a=:443 -hostname=x.x.x.x -certmode=manual -certdir=/var/lib/derper/certs -http-port=-1 -stun-port=3478
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

保存后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable derper
sudo systemctl start derper
```

检查服务：

```bash
sudo systemctl status derper
```

查看实时日志：

```bash
sudo journalctl -u derper -f
```

正常启动时可看到类似日志：

```text
STUN server listening on [::]:3478
derper: serving on :443 with TLS
Using self-signed certificate for IP address "x.x.x.x"
```

### 5.7 配置腾讯云安全组

放行以下入站端口：

| 端口 | 协议 | 用途 |
|---|---|---|
| 443 | TCP | DERP HTTPS/TLS |
| 3478 | UDP | STUN |
| 22 | TCP | SSH 管理（按需限制来源） |

本次 DERP 未启用普通 HTTP 服务，不需要开放 80 端口。

检查监听：

```bash
sudo ss -lntup
```

应能看到 TCP `*:443` 和 UDP `*:3478` 监听。

## 6. 将自建 DERP 加入 Tailscale

进入 Tailscale 管理后台：

https://login.tailscale.com/admin/acls

在现有 Tailnet 策略最外层添加 `derpMap` 字段。不要覆盖原有的 `grants`、`ssh`、`nodeAttrs` 等策略。

本次配置：

```json
"derpMap": {
  "Regions": {
    "900": {
      "RegionID": 900,
      "RegionCode": "bj",
      "RegionName": "Beijing",
      "Nodes": [
        {
          "Name": "custom",
          "RegionID": 900,
          "HostName": "x.x.x.x",
          "IPv4": "x.x.x.x",
          "DERPPort": 443,
          "STUNPort": 3478,
          "CertName": "x.x.x.x"
        }
      ]
    }
  }
}
```

保存后，在 Mac 和 Windows 上检查 DERP 地图：

```bash
tailscale debug derp-map
```

Mac 使用完整 CLI 路径执行。确认列表中出现 Region 900。

## 7. 配置 Windows ComfyUI 远程访问

### 7.1 确认 ComfyUI 本机可访问

在 Windows 上确认 ComfyUI 正常运行，并监听：

```text
http://127.0.0.1:8188
```

PowerShell 测试：

```powershell
curl.exe http://127.0.0.1:8188/system_stats
```

返回 JSON 即表示 ComfyUI HTTP API 正常。

### 7.2 配置 Tailscale Serve

在 Windows PowerShell 中执行：

```powershell
tailscale serve --bg 8188
```

检查：

```powershell
tailscale serve status
```

本次配置结果：

```text
https://desktop-xxxx.tailxxxx.ts.net (tailnet only)
|-- / proxy http://127.0.0.1:8188
```

Tailscale Serve 的作用：

- 提供 Tailnet 内可访问的 HTTPS 入口。
- 将请求代理到 Windows 本机 ComfyUI。
- 不需要把 8188 直接开放到公网。
- 不需要在家庭路由器配置公网端口映射。

最终访问地址：

https://desktop-xxxx.tailxxxx.ts.net/

### 7.3 Mac 浏览器访问

在 MacBook 的 Chrome 中打开：

```text
https://desktop-xxxx.tailxxxx.ts.net/
```

正常情况下即可进入 ComfyUI 节点界面。

如果页面一直加载，可按以下顺序排查：

1. 访问 `/system_stats`，确认是否返回 JSON。
2. 打开 Chrome 开发者工具：`Option + Command + I`。
3. 进入 Network，过滤 `WS`。
4. 检查 `/ws` WebSocket 请求是否成功。

WebSocket 的 `101` 状态表示握手成功；连接保持 `Pending` 通常是正常现象。

## 8. 优先使用北京 DERP

### 8.1 手动指定优先区域

在 Mac 上执行：

```bash
"/Applications/Tailscale.app/Contents/MacOS/Tailscale" debug force-prefer-derp 900
```

其中 `900` 是自建北京 DERP 的 Region ID。

### 8.2 检查连接状态

```bash
"/Applications/Tailscale.app/Contents/MacOS/Tailscale" ping desktop-xxxx
```

本次实测结果：

```text
pong from desktop-xxxx (x.x.x.x) via DERP(bj) in 48ms
```

此前使用东京 DERP 时，延迟约为 395ms；切换北京后约为 48ms。

### 8.3 开机后重新执行

用户已自行编写 Mac 脚本，在开机后手动执行以下命令：

```bash
"/Applications/Tailscale.app/Contents/MacOS/Tailscale" debug force-prefer-derp 900
```

该命令属于临时优先设置，客户端重启后可能需要重新执行。

不建议删除其他官方 DERP 区域，以便北京 VPS 不可用时保留备用中继。

## 9. 网络测试与结果

### 9.1 初始网络情况

Mac 和 Windows 的 `tailscale netcheck` 均显示 UDP 可用，但设备间没有成功建立 Direct P2P 连接。

河北家庭网络存在多层 NAT：

```text
Windows
  ↓
家庭路由器
  ↓
光猫
  ↓
运营商网络
```

家庭宽带 PPPoE 接口取得了 `10.x` 私有 IPv4 地址，结合公网检测结果，存在运营商 CGNAT 的可能。

### 9.2 切换北京中继前后

| 状态 | Tailscale 中继 | 实测延迟 |
|---|---|---:|
| 切换前 | 东京 DERP | 约 395ms |
| 切换后 | 北京 DERP | 约 48ms |

以上是 `tailscale ping` 的中继往返延迟，不代表大文件传输吞吐量按相同比例提升。实际传输速度还受 VPS 带宽、网络路径和拥塞影响。

### 9.3 最终 ComfyUI 测试

最终结果：

- Mac 可以正常访问 Windows 上的 ComfyUI。
- 节点界面成功加载。
- HTTP API 正常。
- WebSocket 正常。
- 节点拖动和工作流操作稳定。
- 实际使用体验反馈：稳定、速度较快，明显优于向日葵远程桌面。

## 11. 安全与维护注意事项

1. 不要将 ComfyUI 的 8188 端口直接暴露到公网。
2. 不要使用 Tailscale Funnel 暴露私人 ComfyUI 服务。
3. 保留 Tailnet 设备访问控制。
4. VPS 只开放必要的 TCP 443、UDP 3478 和 SSH 管理端口。
5. 定期更新 Ubuntu 和 DERP 程序。
6. 升级 DERP 时检查证书指纹和 Tailnet `derpMap` 配置。
7. 备份 `/etc/systemd/system/derper.service`、证书和 DERP 密钥。
8. 不要随意删除 `/var/lib/derper/certs` 或 `/var/lib/derper/derper.key`。
