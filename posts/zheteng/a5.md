## 1. 项目目标与风格方向

本项目以 Hatsune Miku 为主体，目标风格从一般二次元插画逐步转向 **SEGA /
Project DIVA Future Tone、Project DIVA Arcade 的游戏内 3D
模型观感**，并结合日系高级 Cosplay 写真质感。

视觉约束：

-   主体必须明确保留 Miku的识别特征：薄荷青色长双马尾、青绿色系眼睛、标志性发色与发型。
-   目标不是普通网红脸或欧美模特脸；面部需要保留 Miku 的理想化特征。
-   质感方向：接近真实摄影的皮肤、发丝、服装材质和光影，但整体仍然是Miku。
-   当前重点参考 Project DIVA Future Tone / Arcade 的 SEGA 3D 模型风格。
-   服装描述尽量写实际服装元素，不要只堆叠抽象风格词。

## 3. 模型与 LoRA

### 3.1 已出现过的 Checkpoint

历史测试中出现过：

-   WAI-Illustrious v16
-   Illustrious-XL v2.0
-   WAI-Illustrious v15

后续基线记录确认采用 **WAI-Illustrious

### 3.2 LoRA

已确认的最终基线组合：

1.  `Project DIVA STYLE`：Model strength 0.8，CLIP strength 0.8。
2.  `Hatsune Miku (World is mine!)`：Model strength 0.8，CLIP strength
    0.8。

World is Mine LoRA 权重测试区间约 0.8--1.1；最终基线记录为两组 LoRA 均 0.8。

World is Mine LoRA 的触发词记录：
`twintails, long hair, blue eyes, blue hair`

> 触发词仅作为该 LoRA 的已记录触发词，不代表每次提示词都必须机械重复。

### 3.3 共享模型目录

模型通常放在 ComfyUI Desktop 的共享目录：

``` text
<共享模型目录>/models/
├── checkpoints/
└── loras/
```

-   Checkpoint 放入 `checkpoints`。
-   LoRA 放入 `loras`。
-   文件放好后，在 ComfyUI 中刷新模型列表；必要时重启。

## 4. 基础 SDXL 工作流

已记录的基础链路：

``` text
Checkpoint Loader
    ├── MODEL ──> LoRA 1 ──> LoRA 2 ──> KSampler
    ├── CLIP  ──> LoRA 1 ──> LoRA 2 ──> Positive CLIP Text Encode
    │                                  └─> Negative CLIP Text Encode
    └── VAE ─────────────────────────────> VAE Decode

Positive / Negative conditioning ────────> KSampler
KSampler samples ────────────────────────> VAE Decode
VAE Decode image ────────────────────────> Save Image
```

LoRA 顺序与连接：

-   Checkpoint → `Project DIVA STYLE`（Model / CLIP 0.8）
-   前一个 LoRA → `Hatsune Miku (World is mine!)`（Model / CLIP 0.8）
-   最终 Model 输出连接 KSampler。
-   最终 CLIP 输出分别连接正向、负向文本编码器。
-   Checkpoint 的 VAE 输出连接 VAE Decode。

### 6.3 动作模块（每次替换）

每次只选用当前需要的动作描述，替换旧动作，不要把互相冲突的动作同时留在 Positive 中。

| 姿势 | Positive 动作描述 |
|---|---|
| 普通站姿 | `standing, relaxed standing pose` |
| 双手叉腰 | `standing, hands on hips` |
| 单手举高 | `one arm raised above head, other hand on hip` |
| 奔跑 | `dynamic running pose, natural running motion` |
| 单腿跪姿 | `one knee kneeling, natural kneeling posture` |
| 深蹲 | `deep squat, both knees deeply bent` |
| 坐姿 | `sitting on a chair, natural seated pose` |
| 后仰 | `leaning backward, dynamic body posture` |
| 跳跃 | `jumping, both feet off the ground, dynamic pose` |

坐姿、跳跃等复杂动作，最好继续使用对应的姿势参考图。

### 6.4 使用规则

每次生成按以下结构组合：

1. 固定角色模块
2. 固定服装模块
3. 本次动作模块
4. 场景、表情模块（可选）

注意事项：

- `standing`、`hands on hips` 等旧动作描述不能残留在新姿势里。
- 不要同时保留互相冲突的动作。
- 角色和服装模块先不动，发现问题再单独修正。
- 每次测试尽量保持 Seed、LoRA 权重、采样参数一致。
- 本模板是通用起点，不是已经验证所有姿势都完美的最终模板；服装部分仍可结合最满意的公式服生成结果继续校准。

## 9. 工作流备份与恢复

建议备份：

1.  `miku_diva.json`
2.  共享模型目录（models/）中实际使用的 Checkpoint 与
    LoRA 文件清单
3.  自定义节点清单与版本
4.  正负向提示词原文
5.  成功姿势的输出图与对应参数

恢复顺序：

1.  安装匹配版本的 ComfyUI。
2.  恢复共享模型目录。
3.  安装工作流依赖的自定义节点。
4.  导入 `miku_diva.json`。
5.  检查模型 / LoRA 是否成功识别。
6.  运行一张低风险测试图，确认采样、解码、保存链路正常。
7.  再恢复高分辨率和姿势控制测试。
