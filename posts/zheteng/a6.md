# Miku 网站： Github 与 .isroot.in 域名部署指南

## 1. 架构概览

当前已验证的访问链路：

``` text
浏览器
  |
  | https://hatsune-miku.isroot.in/
  v 
Hurricane Electric DNS
  |
  v
Cloady 自定义域名入口
  |
  | HTTPS / Let's Encrypt
  | HTTP 301
  v
https://hatsunemiku.isroot.in/
  |
  v
GitHub Pages 主站
  |
  v
HTTP 200 OK
```

域名分工：

  域名                       角色              服务
  -------------------------- ----------------- --------------------
  `hatsunemiku.isroot.in`    主站域名          GitHub Pages
  `hatsune-miku.isroot.in`   别名 / 跳转域名   Cloady Node.js 301

主站与别名域名是两个独立的 HE DNS zone。不要将 zone 内 NS
记录与父级注册商的 NS delegation 混为一谈。

## 2. GitHub Pages 主站

主站：

``` text
https://hatsunemiku.isroot.in
```

GitHub Pages IPv4 地址记录（主站使用）：

``` text
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

GitHub Pages 的 Custom Domain
对单个站点配置一个主自定义域名。别名域名仅通过 DNS 指向主站，并不等于
HTTP 重定向；GitHub Pages 仍会根据请求的 Host
识别站点，因此未配置为该站点自定义域名时可能返回 404。

最终采用独立跳转服务解决别名入口问题。

### 强制 HTTPS

GitHub Pages 设置中已开启 **Enforce HTTPS**。

作用：

-   主站通过 HTTPS 提供访问。
-   HTTP 访问会被引导到 HTTPS。
-   浏览器不再因主站使用 HTTP 而显示不安全警告。

> IP。

### 关于 ALIAS 的踩坑记录

早期尝试在别名 zone apex 配置：

``` text
hatsune-miku.isroot.in  ALIAS  hatsunemiku.isroot.in
```

观察到 HE 五台权威 DNS 对该 ALIAS 的 A 查询响应不一致：部分节点返回四条
GitHub Pages A 记录，部分节点暂时没有返回记录；当时五台 SOA serial
相同。公共递归解析器也曾查询不到 A 记录。

重要结论：

-   ALIAS 是 DNS 服务商提供的扩展能力，不是标准 DNS 资源记录类型。
-   ALIAS 不是 HTTP 重定向，浏览器地址栏不会自动变成主域名。
-   即使别名解析到 GitHub Pages 的 IP，GitHub Pages 仍会收到别名
    Host，可能因自定义域名不匹配而返回 404。
-   最终不再依赖 ALIAS，改由 Cloady 执行 HTTP 301。

## 4. Cloady Node.js 跳转应用

Cloady 项目用途：只负责接收别名域名请求并返回 301，不承载主站内容。

### `server.js`

``` javascript
const http = require("node:http");

const TARGET = "https://hatsunemiku.isroot.in";

http.createServer((req, res) => {
  const incoming = new URL(req.url, "http://localhost");
  const destination = new URL(TARGET);

  destination.pathname = incoming.pathname;
  destination.search = incoming.search;

  res.writeHead(301, {
    Location: destination.toString(),
    "Cache-Control": "no-store"
  });

  res.end();
}).listen(process.env.PORT || 3000, "0.0.0.0");
```

说明：

-   使用 `process.env.PORT`，遵循 Cloady 平台分配的端口。
-   监听 `0.0.0.0`，使容器服务可从外部访问。
-   保留原始请求路径与 query string。
-   返回 `301` 永久重定向。
-   `Cache-Control: no-store` 用于避免跳转响应被缓存，方便维护和验证。
-   URL
    fragment（`#...`）不会发送到服务器，因此无法由服务端代码保留；浏览器对
    fragment 的处理遵循 HTTP 重定向规则。

### `package.json`

``` json
{
  "name": "miku-redirect",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "start": "node server.js"
  }
}
```

部署方式：代码托管在 GitHub，Cloady 从 GitHub 拉取并构建 / 部署 Node.js
应用。更新代码后等待 Cloady 部署完成，再执行 curl 验证。

## 8. 已知限制与故障排查

### 浏览器显示"不安全"

分别检查：

1.  访问的是否为 `https://`。
2.  Cloady 自定义域名是否已成功签发证书。
3.  GitHub Pages 的 Enforce HTTPS 是否已开启。
4.  `curl -Iv` 是否显示证书验证成功。

### GitHub Pages 返回 404

如果 DNS 已指向 GitHub Pages，但请求域名不是 Pages 当前配置的 Custom
Domain，GitHub Pages 可能因 Host 不匹配返回 404。

不要只靠 DNS ALIAS 解决。别名域名需要配置成 Pages
支持的自定义域名，或像本项目一样使用 HTTP 301 跳转。
